# Инструменты QA

Всё, что нужно тестировщику, делается в веб-админке: «Игроки» → найти игрока → нужная карточка. Под капотом — admin API на ops-порту с `X-Admin-Key`, поэтому из игры и из интернета эти ручки недоступны. План и следующие фазы — `.ai-factory/plans/qa-tools.md`.

## Где что включено

| Окружение | Тестовые аккаунты и поиск | Читы |
| --- | --- | --- |
| Local, dev, stage | да | да |
| prod | да | нет: `Cheats:Enabled = true` в Production не даёт серверу стартовать |

Без `Cheats:Enabled` эндпоинты читов не регистрируются вовсе, а админка показывает бейдж «читы выключены» и прячет формы.

Все читы доступны роли `tester`. Удаление аккаунта — только `admin`.

## Как QA работает с аккаунтом

1. Запустить игру на устройстве. Сервер создаёт аккаунт по `deviceId` и профиль со стартовым набором.
2. В админке на вкладке «Игроки» найти себя по `userId` или `deviceId` и нажать «Пометить как тестовый» с псевдонимом, например `qa-masha-1`.
3. Дальше искать себя по псевдониму. Список всех тестовых аккаунтов окружения — на вкладке «Игроки», если ничего не искать.

Что даёт метка:

- аккаунт выходит из A/B-эксперимента (назначение стирается) и больше в эксперименты не попадает, то есть всегда играет на мастер-конфигах;
- аналитика в админке по умолчанию не считает такие аккаунты: обзор, конструктор отчётов и результаты экспериментов. Галочка «тестовые аккаунты» / «Показать тестовые аккаунты» возвращает их в отчёт;
- события самого игрока в его карточке видны всегда.

Пока клиент не показывает `userId` на экране, `deviceId` проще всего взять из логов клиента. Просьба к клиентской команде вывести `userId` в настройках — в фазе 3 плана.

## Читы

| Что | Как работает |
| --- | --- |
| Выдать награду | список из текущих конфигов (ресурсы, персонажи, саммоны, снаряжение, бонусы аккаунта) и количество. Работает как обычная награда: копии тратятся на прокачку, выдаются награды уровней. Ниже — старая форма строкой `тип:id:кол-во` |
| Все персонажи / Все саммоны | открывает тех, кого у игрока ещё нет, по одной копии |
| Всё снаряжение | по одному предмету каждого конфига |
| Каждого ресурса | прибавляет N к каждому ресурсу, который встречается в конфигах |
| Выдать всё | всё перечисленное и по 100 000 каждого ресурса |
| Максимум всему | имеющимся персонажам, саммонам и снаряжению ставит максимальный уровень, мастерство, скиллы и промоут по конфигам |
| Ресурс = X | ставит точное значение, в том числе 0, чтобы проверить нехватку |
| Промоут персонажа | 1…максимум; если персонажа нет — открывает его |
| Саммон | уровень, мастерство, уровень всех скиллов; если саммона нет — открывает его |
| Уровень снаряжения | 1…максимум для конкретного предмета |
| Флаг аккаунта | точное значение, 0 удаляет флаг |
| Прервать забег | переводит активный забег в `abandoned`, как кнопка выхода в игре |
| Сбросить прогресс | удаляет профиль, забеги, журнал и ключи идемпотентности; аккаунт и устройство остаются, клиенту не нужно перелогиниваться. При следующем запросе профиля игрок получит стартовый набор |

Правила прокачки читами:

- повышение промоута и мастерства проходит уровень за уровнем и выдаёт награды каждого уровня (сцены, ресурсы, бонусы), как обычная прокачка;
- понижение не забирает уже выданное;
- уровень скиллов не выше максимума каждого скилла, требования мастерства и уровня саммона не проверяются;
- ресурсы на прокачку не списываются.

Каждый чит пишется в журнал игрока (`player_ledger`) с действием `cheat` и источником `admin:<логин>:cheat:<операция>`; пресеты «выдать» — с действием `grant`. В логах сервера — тег `[Cheat]`, метка аккаунта — `[Qa]`. Все действия админки дополнительно в её `audit.log`.

Профиль меняется с проверкой `rev`: если игрок в этот момент что-то делает в игре, чит повторится до трёх раз, иначе админка покажет 409 и действие нужно повторить. Клиент увидит изменения после следующего запроса профиля — обычно после перезахода на экран или в игру.

Читы применяются к профилю, у которого он уже есть: игрок должен хотя бы раз открыть игру.

## Любой прогресс за секунды

### Сюжет

Карточка «Сюжет»: галочки пройденных уровней. Сохраняется точный список; от него зависят триггеры доступа уровней (`story_level_completed`, `story_level_not_completed`).

### Шаблоны прогресса

Шаблон — копия профиля игрока под именем: ресурсы, персонажи, саммоны, снаряжение, бонусы аккаунта, лоадаут, пройденные уровни, флаги.

- «Сохранить прогресс этого игрока как шаблон» — ключ (`a-z 0-9 - _`, 2–32 символа), название, описание. Шаблон с тем же ключом перезаписывается.
- «Применить» — заменяет профиль игрока шаблоном целиком. Активный забег прерывается.
- «Взять прогресс у другого игрока» — то же, но источник — профиль другого игрока (по `userId`, псевдониму или `deviceId`).
- Аккаунт, устройство, A/B-группа и журнал при этом не меняются, ревизия профиля растёт — клиент перечитает профиль.
- Список шаблонов и удаление — на вкладке «Игроки» без поиска.

Шаблоны живут в базе своего окружения (`qa_templates`): шаблон dev не виден на stage. Шаблон не проверяется на совместимость с конфигами: если после смены таблиц в нём остался удалённый персонаж или предмет, сервер его просто не найдёт. Версия конфигов, на которой шаблон сохранён, видна в списке.

### Забег

Карточка «Забег» показывает активный забег: этапы с событиями, здоровье, опыт, перки, бонусы, статусы, ожидаемый выбор. Правки применяются к документу забега, конфиги — той версии, на которой забег запущен.

| Что | Как работает |
| --- | --- |
| Перейти сюда | ставит забег на этап N: предыдущие считаются пройденными, следующие — нет; открытая развилка закрывается. Возврат на пройденный бой повторяет тот же бой: seed боя считается от забега и номера этапа |
| Поставить событие | меняет событие текущего или будущего этапа: сначала варианты этого этапа из `Story_stages`, ниже — все события |
| Здоровье | текущее здоровье героя в забеге |
| Перки | добавить любой перк или убрать; при удалении сбрасываются и использования (воскрешение) |
| Бонусы забега | бонус × количество на N боёв, 0 — до конца забега |
| Статусы | статусы на следующий бой, после боя снимаются, как обычно |
| Очистить | убрать все перки, бонусы или статусы |

«Лёгкий бой» делается бонусом забега: например, бонус на здоровье или урон × 20 до конца забега. Отдельного режима победы нет: исход боя считает только боевое ядро, читы его не трогают и golden-эталоны не меняются.

Опыт и уровень прохождения напрямую не выставляются: level-up запускает выбор перков, проще добавить нужные перки.

Клиент увидит изменения забега после повторного запроса `GET /api/run/current`, то есть после перезахода в забег.

## Admin API

Все пути — на ops-порту, заголовки `X-Admin-Key` и необязательный `X-Admin-Actor`.

| Эндпоинт | Метод | Тело | Что делает |
| --- | --- | --- | --- |
| `/admin/qa/status` | GET | — | `{cheatsEnabled, environment}` |
| `/admin/qa/catalog` | GET | — | персонажи, саммоны, снаряжение с максимальными уровнями, бонусы аккаунта, ключи ресурсов, уровни сюжета из мастер-конфигов |
| `/admin/qa/players` | GET | — | список тестовых аккаунтов |
| `/admin/qa/find?query=` | GET | — | поиск по `userId`, псевдониму и `deviceId`; ответ — список `{userId, alias, matchedBy}` |
| `/admin/qa/players/{userId}` | GET | — | `{userId, isQa, alias, markedBy, markedAt, createdAt}` |
| `/admin/qa/players/{userId}/mark` | POST | `{alias}` | пометить тестовым: 2–32 символа `a-z 0-9 - _`, уникален в окружении |
| `/admin/qa/players/{userId}/mark` | DELETE | — | снять метку |
| `/admin/qa/players/{userId}/cheats/preset` | POST | `{preset, amount}` | `characters`, `summons`, `equipment`, `resources`, `everything` |
| `/admin/qa/players/{userId}/cheats/resource` | POST | `{key, amount}` | ресурс = `amount` |
| `/admin/qa/players/{userId}/cheats/flag` | POST | `{key, value}` | флаг = `value` |
| `/admin/qa/players/{userId}/cheats/character/{id}` | POST | `{promoteLevel}` | промоут персонажа |
| `/admin/qa/players/{userId}/cheats/summon/{id}` | POST | `{level?, masteryLevel?, skillLevel?}` | уровень, мастерство, скиллы саммона |
| `/admin/qa/players/{userId}/cheats/equipment/{instanceId}` | POST | `{level}` | уровень предмета |
| `/admin/qa/players/{userId}/cheats/max` | POST | — | максимум всему имеющемуся |
| `/admin/qa/players/{userId}/cheats/run/abandon` | POST | — | прервать активный забег |
| `/admin/qa/players/{userId}/cheats/reset` | POST | — | сбросить прогресс |
| `/admin/qa/players/{userId}/cheats/story` | POST | `{completedLevelIds}` | пройденные уровни сюжета |
| `/admin/qa/players/{userId}/cheats/template` | POST | `{templateId}` | применить шаблон, активный забег прерывается |
| `/admin/qa/players/{userId}/cheats/copy` | POST | `{sourceUserId}` | взять профиль другого игрока, активный забег прерывается |
| `/admin/qa/players/{userId}/cheats/run` | POST | `{action, stage, id, value, count, battles}` | изменить активный забег: `stage`, `event`, `health`, `perk`, `remove-perk`, `bonus`, `status`, `clear-perks`, `clear-bonuses`, `clear-statuses`; ответ — состояние забега |
| `/admin/qa/players/{userId}/run` | GET | — | активный забег для карточки «Забег» или 404 |
| `/admin/qa/templates` | GET | — | список шаблонов с кратким содержимым |
| `/admin/qa/templates` | POST | `{templateId, name, description, userId}` | сохранить профиль игрока как шаблон |
| `/admin/qa/templates/{templateId}` | DELETE | — | удалить шаблон |

Шаблоны, забег и все `cheats/*` доступны только при `Cheats:Enabled`. Изменяющие профиль читы отвечают профилем в том же формате, что `/admin/player/{userId}`; ошибки — `400 {errors: [...]}`, гонка — `409`.

Пример для скриптов:

```bash
curl -s -X POST "http://127.0.0.1:9090/admin/qa/players/usr_…/cheats/summon/3" \
  -H "X-Admin-Key: $ADMIN_KEY" -H "X-Admin-Actor: script:qa" \
  -H "Content-Type: application/json" -d '{"level":20,"masteryLevel":5}'
```

## Хранение

- `users.qa` — `{alias, markedBy, markedAt}`, уникальный sparse-индекс `qa.alias_1`.
- `qa_templates` — `{_id: ключ, name, description, createdBy, sourceUserId, configVersion, profile}`; `profile` — тот же документ, что в `player_profiles`.
- Читы забега пишут в лог `[Cheat] run changed`, замену профиля шаблоном или копией — `[Cheat] profile replaced` и запись в журнал игрока с источником `admin:<логин>:cheat:template:<ключ>` или `cheat:copy:<userId>`.
- Исключение из аналитики делает админка: перед отчётом берёт список тестовых аккаунтов окружения и добавляет `user_id NOT IN (...)`. Поэтому метка действует и на события, которые пришли до неё.
