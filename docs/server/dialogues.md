# Диалоги: конфиг, запуски и подтверждение показа

Диалоги — нарративная механика из ГДД (раздел «Диалоги», GDD_new9): сцены с фоном, спрайтами персонажей, текстом и выборами. Ими показывают сюжет уровней и награды (свидания и другой нарратив).

Сервер решает, **когда** показать диалог, и помнит, что уже показано. Клиент показывает и подтверждает показ. Содержимое диалога клиент читает из того же снапшота конфигов (`ISharedCore.Configs.Dialogues`).

## Лист `Dialogues`

Одна строка — один шаг диалога. Ключ — `id` + `step`.

| Колонка | Что значит |
| --- | --- |
| `id` | номер диалога |
| `step` | номер шага, диалог начинается с шага 1 |
| `next_step` | следующий шаг; несколько через `;` — по одному на вариант выбора; пусто — конец диалога |
| `is_fade_on_start` | `TRUE` — затемнение перед шагом |
| `dialogue_characters_visible` | спрайты на экране: `имя:процент;имя:процент`, процент — позиция по ширине экрана (0–100) |
| `current_character_loc_name` | ключ имени говорящего; пусто — плашка имени скрыта |
| `backgrounds` | фоны через `;`; пусто — фон прошлого шага |
| `music` | трек музыки шага |
| `sounds` | оркестры звуков по фонам через `;`, порядок как у `backgrounds`; пустое место — без звука (`wind;`) |
| `localization_keys` | первый ключ — текст шага, остальные — варианты выбора |
| `text_speed` | скорость печати, символов в секунду |

Лист необязательный: снапшот без него загружается, диалогов просто нет.

Проверки при публикации (ошибки блокируют публикацию):

- шаг записан дважды, в диалоге нет шага 1, пустой `localization_keys`;
- вариантов выбора больше одного, а переходов в `next_step` другое число;
- без вариантов выбора больше одного перехода;
- `next_step` ведёт на шаг, которого нет;
- `text_speed` не больше нуля;
- из шага нельзя дойти до конца диалога. Циклы разрешены, если из них есть выход.

Предупреждения (не блокируют): процент спрайта вне 0–100, число оркестров в `sounds` не совпадает с числом фонов.

## Диалоги уровня в `Story_levels`

Две необязательные колонки, списки через `;` одинаковой длины:

- `dialogues_ids` — номера диалогов;
- `dialogues_triggers` — когда показать каждый: `on_start`, `on_win`, `on_loss`, `on_stage_entered:N` (N — номер этапа с 1).

Пример: `dialogues_ids = 1;3`, `dialogues_triggers = on_stage_entered:2;on_win`.

Ошибки публикации: длины списков разные, диалога нет в листе `Dialogues`, триггер не распознан, этапа N нет в уровне.

Диалог уровня показывается **один раз на аккаунт**: ключ запуска — `level:{storyLevelId}:{dialogueId}:{trigger}`. Пока показ не подтверждён, сервер присылает его снова.

## Награда `dialogue:<id>:<n>`

Ставит диалог в очередь профиля `n` раз. Каждый запуск получает свой ключ `reward:{dialogueId}:{guid}` и ждёт подтверждения. Диалога нет в листе — Warning и пропуск. Награда приходит в `appliedRewards` с типом `Dialogue`, в `rewardTotals` забега не попадает.

`story:<id>:<n>` по-прежнему открывает сцены персонажа и саммона, к диалогам он не относится.

## Когда сервер присылает диалоги

`pendingDialogues: [{launchKey, dialogueId, trigger}]` есть в каждом ответе забега и в профиле. `trigger` — `on_start`, `on_stage_entered:N`, `on_win`, `on_loss` или `reward`; по нему клиент выбирает момент показа и не разбирает `launchKey`. Порядок: сначала диалоги уровня в порядке `dialogues_ids`, потом награды в порядке выдачи. Награда, чьего диалога нет в текущем конфиге (лист поправили после выдачи), не отдаётся клиенту и остаётся в профиле, пока диалог не вернут.

| Ответ | Диалоги уровня |
| --- | --- |
| `POST /api/run/start` | `on_start` |
| `POST /api/run/advance` | `on_stage_entered:N`, где N — этап, в который вошли этим шагом |
| шаг, завершивший забег | `on_win` |
| `battle/finish` с поражением, `abandon` | `on_loss` |
| `GET /api/run/current`, повтор шага (`replayed`) | `on_start` на первом этапе, `on_stage_entered:N` пока этап не закрыт (ждёт `battle/finish` или выбор развилки) |

Награды-диалоги (`reward:…`) приходят в любом ответе забега и в `GET /api/player/profile`, пока не подтверждены.

Если ответ шага, закрывшего забег, потерян, `on_win` и `on_loss` этого забега больше не придут: `GET /api/run/current` уже отвечает `404`. Диалог покажется в следующем забеге уровня.

## `POST /api/dialogue/complete`

```json
{ "requestId": "…", "launchKey": "level:1:1:on_start", "picks": [1] }
```

Звать после того, как игрок дочитал диалог. `picks` — номера выбранных вариантов (с 1) в порядке шагов с выбором.

Ответ — профиль (`GET /api/player/profile`). Запуск переезжает в `dialogues.completed` вместе с `picks`, награда уходит из очереди.

- Повтор с тем же `launchKey` — `200` без изменений, `picks` первого подтверждения сохраняются.
- `400`: пустой `launchKey`; награды с таким ключом нет в очереди; у уровня нет такого диалога с таким триггером; `picks` не проходят по графу диалога (нет выбора на развилке, номер вне вариантов, лишние выборы).
- Проверка идёт по конфигу запроса: во время забега — закреплённому за забегом, вне забега — текущему. Если не прошла, сервер повторяет её по конфигу последнего забега игрока: `on_win` и `on_loss` подтверждаются уже после конца забега, а клиент играл диалог из его снапшота.
- `409`: профиль трижды подряд менялся параллельно, повторить позже.

Выборы пока только ведут по шагам. Сервер хранит их, чтобы потом давать за них награды или делать платными.

## Профиль

```json
"dialogues": {
  "pending": [ { "launchKey": "reward:3:…", "dialogueId": 3, "createdAt": "…" } ],
  "completed": [ { "launchKey": "level:1:1:on_start", "dialogueId": 1, "picks": [1], "completedAt": "…" } ]
}
```

Это документ Mongo. Клиент видит только `pendingDialogues`.

Сброс прогресса и удаление аккаунта убирают всё. В админке на карточке игрока видна очередь, кнопка «Сбросить диалоги» (QA, `POST /admin/qa/players/{userId}/cheats/dialogues/reset`) очищает очередь и показанные — диалоги уровней покажутся снова.

## Аналитика

`dialogue_completed`: `launch_key`, `dialogue_id`, `picks` через `;`.
