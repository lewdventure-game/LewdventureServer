# Эксперименты (A/B на снапшотах конфигов)

Эксперимент раздаёт разным игрокам разные снапшоты конфигов. Кто не попал ни в одну группу, играет на мастере — активной версии `config_state.active`. Как сервер держит несколько версий сразу, описано в [config-sync](config-sync.md#несколько-версий-одновременно).

Тестовые аккаунты QA в автоназначение не попадают и в участниках групп не считаются; вручную включить такой аккаунт в группу можно из админки — см. [qa-tools.md](qa-tools.md#группа-ab-для-тестового-аккаунта).

## Модель

| Сущность | Где | Что |
| --- | --- | --- |
| Эксперимент | `experiments` | `id`, `name`, `description`, `status` (`draft` → `running` → `finished`), группы, `startedAt`, `finishedAt`, `rev` |
| Группа | `experiments.groups[]` | `id`, `snapshotVersion`, `percent` (доля от подходящих под фильтр игроков), `filter.newPlayersOnly`, `filter.countries` (ISO alpha-2, пусто = все), `status` (`recruiting`, `frozen`, `removed`) |
| Журнал | `experiment_changes` | кто, когда, какое действие, с какой группой и почему |
| Назначение | `users.experiment` | `experimentId`, `groupId`, `assignedAt`, `country` |
| Уже разыгранные | `users.experimentsSeen` | эксперименты, в которых игрок участвовал в розыгрыше; повторно не разыгрываются |
| Страна | `users.country`, `users.lastCountry` | из заголовка Cloudflare `CF-IPCountry` при создании аккаунта и при каждом входе, `XX` если неизвестна |

## Назначение

- Когда: на `POST /api/auth/device` (новый аккаунт считается новым игроком) и `POST /api/auth/refresh`.
- Игрок в активной группе (эксперимент `running`, группа не `removed`) не разыгрывается.
- Кандидаты — группы `recruiting` всех `running` экспериментов, кроме уже разыгранных, с подходящим фильтром: `newPlayersOnly` только для только что созданного аккаунта, страна — текущая страна запроса.
- Одно случайное число от 0 до 100. Группы в порядке старта экспериментов и порядке групп внутри занимают подряд отрезки длиной `percent`. Не попал ни в одну — мастер. Все эксперименты-кандидаты отмечаются разыгранными.
- Запись условная (`experiment` не изменился с момента чтения), гонка двух устройств не даёт двойного назначения.
- Одна группа за раз. Игрок из удалённой группы или законченного эксперимента снова может попасть в новые эксперименты без `newPlayersOnly`.

Пример — сценарий 2 из постановки: три группы по 25% для новых из США и эксперимент 10% + 10% по миру. Новый игрок из США попадает в группы с вероятностями 25, 25, 25, 10, 10 и на мастер с 5%. Игрок из Германии — 10, 10 и мастер 80%. Проверяется `ExperimentScenarioTests`.

## Какая версия конфигов у игрока

`PlayerConfigVersionResolver` для каждого запроса игрока:

1. активный забег — версия забега, даже если группу уже удалили: забег доигрывается на своих правилах;
2. игрок в активной группе — `snapshotVersion` группы;
3. иначе мастер.

Реестр запущенных экспериментов (`ExperimentRegistry`) живёт в памяти: грузится при старте, перечитывается после каждой операции admin API и раз в 30 секунд (`ExperimentRegistryWatcher`).

## Проверки при старте эксперимента

- Структура: id из `a-z 0-9 _ -` до 40 символов, хотя бы одна группа, уникальные id групп, `0 < percent ≤ 100`, снапшот указан, страны — две заглавные латинские буквы.
- Сумма `percent` групп `recruiting` всех запущенных экспериментов для любой страны не больше 100. Проверяются все упомянутые страны и «остальные» (группы без стран).
- Снапшот каждой группы опубликован и собирается.
- Снапшот не удаляет id, которые есть в мастере (`ConfigSnapshotDiff`): игрок, переведённый на мастер, не должен получить неизвестные id. Изменённые значения — норма.

## Admin API

Ops-порт, `X-Admin-Key`. Ответы с ошибками: 400 — невалидно, 404 — не найдено, 409 — неподходящий статус или параллельное изменение.

| Метод и путь | Тело | Действие |
| --- | --- | --- |
| `GET /admin/experiments?limit=` | | список с числом участников по группам |
| `POST /admin/experiments` | `{id, name, description, groups: [{id, name, snapshotVersion, percent, newPlayersOnly, countries}]}` | создать черновик |
| `GET /admin/experiments/{id}` | | эксперимент с участниками |
| `DELETE /admin/experiments/{id}` | | удалить черновик |
| `GET /admin/experiments/{id}/changes` | | журнал |
| `POST /admin/experiments/{id}/start` | `{reason}` | запустить с проверками |
| `POST /admin/experiments/{id}/groups/{groupId}/freeze` | `{reason}` | остановить набор, участники остаются на снапшоте |
| `POST /admin/experiments/{id}/groups/{groupId}/remove` | `{reason}` | вывести группу на мастер |
| `POST /admin/experiments/{id}/finish` | `{reason}` | закончить, все на мастер |
| `POST /admin/experiments/{id}/rollout` | `{groupId, reason}` | активировать снапшот группы как мастер и закончить |
| `GET /admin/experiments/player/{userId}` | | назначение игрока и версия конфигов, которую он сейчас получит |

Сценарий 1 из постановки:

```bash
curl -s -H "X-Admin-Key: $KEY" -H "Content-Type: application/json" http://127.0.0.1:9091/admin/experiments -d '{
  "id": "balance-2026-10", "name": "Баланс урона",
  "groups": [
    {"id": "control", "snapshotVersion": "sha256:<мастер>", "percent": 15, "newPlayersOnly": true},
    {"id": "test", "snapshotVersion": "sha256:<новый>", "percent": 15, "newPlayersOnly": true}
  ]}'
curl -s -X POST -H "X-Admin-Key: $KEY" http://127.0.0.1:9091/admin/experiments/balance-2026-10/start
curl -s -X POST -H "X-Admin-Key: $KEY" -H "Content-Type: application/json" http://127.0.0.1:9091/admin/experiments/balance-2026-10/rollout -d '{"groupId": "test"}'
```

Контрольная группа закреплена на снапшоте мастера на момент старта: если мастер потом обновится, контроль останется на прежней версии и будет сравним с тестом.

## Ограничения

- Новый игрок — новый `deviceId`: после переустановки игрок разыгрывается заново.
- Экспериментальный снапшот не получает правки мастера: исправление бага в мастере нужно публиковать и в снапшоты групп (новый снапшот → новый эксперимент).
- Прогресс-фильтры (игрок достиг N) не реализованы.
- Лог-тег: `[Experiment]`.
