# Для клиентской команды: что показать QA

Сервер собирает всё, что нужно для разбора бага: запросы игрока с ошибками, ошибки сервера, журнал выдач, баг-репорт одним файлом. Чтобы QA мог быстро найти себя и свой запрос, клиенту нужно немного: показать два идентификатора и, по желанию, отправлять версию клиента. Код за клиент сервер не пишет — ниже только контракт и рекомендации.

## 1. userId на экране

`userId` приходит в ответе `POST /api/auth/device` (поле `userId`, вида `usr_<32 hex>`).

- Показать его в настройках или в отладочной панели мелкой строкой, с кнопкой «Скопировать».
- В dev/stage-сборках можно показывать постоянно в углу экрана вместе с окружением и версией клиента.

QA вставляет `userId` в поиск админки и видит профиль, забег, запросы и ошибки. Без него QA ищет себя по `deviceId`, что неудобно.

## 2. correlationId в окне ошибки

Каждый ответ сервера содержит заголовок `X-Correlation-Id`. По нему в админке («Ошибки» → поиск) находится конкретный запрос: тело запроса, ответ, исключение на сервере.

- При любой ошибке запроса (сеть, 4xx, 5xx) показывать в окне ошибки `X-Correlation-Id` ответа и кнопку «Скопировать».
- Писать его в клиентский лог рядом с путём и статусом.
- Можно задавать свой: клиент присылает `X-Correlation-Id` (латиница, цифры и `-`, до 64 символов), сервер использует его и возвращает тот же. Удобно генерировать GUID на запрос и логировать его до отправки — тогда id есть даже при обрыве сети.

## 3. Версия клиента в запросах (по желанию)

Заголовок `X-Client-Version: <версия сборки>` во всех запросах к `/api/*`. Сервер сохраняет его в трассе запросов, и в админке видно, с какой сборки пришёл запрос. До 64 символов.

## 4. Кнопка «Скопировать отладочную информацию» (по желанию)

Одна кнопка в настройках, которая кладёт в буфер:

```text
userId: usr_…
environment: dev
client: 0.12.3 (build 456)
last correlationId: 3f2a…
device: <модель, ОС>
```

QA вставляет это в задачу — разработчику не нужно ничего спрашивать.

## Что видит QA в админке

| Где | Что |
| --- | --- |
| «Игроки» → игрок → «Запросы игрока» | последние запросы: статус, путь, время ответа, correlationId; у ошибок — тело запроса и ответа |
| «Ошибки» | предупреждения и ошибки сервера за 7 дней, поиск по `correlationId` и `userId` |
| «Игроки» → игрок → «Скачать баг-репорт» | JSON со всем состоянием игрока для приложения к задаче |

Трасса запросов и ошибки собираются только на dev и stage, хранятся 7 дней. Запросы `/api/auth/*` сохраняются без тела, `/api/analytics/*` не сохраняются вовсе. Токены и заголовки не сохраняются.
