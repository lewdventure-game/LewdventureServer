# Песочница баланса

Раздел «Баланс» в веб-админке. Геймдизайнер собирает состояние игрока и прогоняет бои тем же ядром, что и игра, на любой опубликованной версии конфигов. Профили и забеги игроков не меняются, в базу ничего не пишется.

План развития по фазам — [`.ai-factory/plans/balance-sandbox.md`](../../.ai-factory/plans/balance-sandbox.md). Готовы все четыре фазы: сетап, характеристики по слоям, один бой, серия боёв, прогон целого уровня, черновые правки конфигов, сравнение A/B, перебор параметра, сценарии и история, очередь тяжёлых прогонов, ссылки, CSV, «Проверить баланс» из таблицы и типичный игрок на прогрессе.

## Как пользоваться

Страница из двух частей. Слева — герой и конфиги, общие для всех задач; сверху панели сводка одной строкой, например «Персонаж 1, промоут 3 · саммонов 2 · предметов 3 · бонусов аккаунта 5 · Конфиги: мастер + 2 правки». Справа — вкладки задач, у каждой одна главная кнопка. Вверху справа — меню «Сценарии».

**Слева: герой и конфиги** (разделы раскрываются по клику):

| Раздел | Что задаёт |
| --- | --- |
| Взять готовый сетап | «У игрока» по `userId` — лоадаут, прокачка, бонусы и текущий забег; «Типичный игрок, который прошёл уровень K» — см. ниже |
| Персонаж | персонаж и уровень промоута |
| Саммоны, Снаряжение | до трёх каждого, с уровнями; у саммона ещё мастерство |
| Бонусы аккаунта | `id:кол-во` через запятую; справочник «Какие бывают» |
| Состояние забега | ХП (0 — полное), перки, бонусы забега `id:кол-во:боёв` (0 — до конца забега), статусы на начало боя. Действует на один бой и серию; прогон уровня всегда начинает забег с нуля |
| Конфиги и правки «что если» | версия (мастер или любой из последних 20 снапшотов) и черновые правки ячеек — см. ниже |

Кнопка «Показать характеристики героя» внизу панели — итоговые здоровье, урон, крит, уклонение и таблица «Откуда что взялось»: база персонажа → + бонусы аккаунта → + снаряжение → + саммоны → + забег, изменения каждого слоя выделены.

**Справа: вкладки**

| Вкладка | Вопрос | Что выбрать |
| --- | --- | --- |
| Бой | пройдёт ли герой этот бой и как часто | бой (уровень, этап, враги) и сколько боёв: 1 — пошагово, 100 / 500 / 2000 — процент побед; в «Дополнительно» — свои враги вместо врагов события и стартовый сид |
| Уровень | сколько этапов пройдёт герой | уровень и сколько раз его пройти (50 / 100 / 300); в «Как играет бот» — политика перков и развилок |
| Сравнить A/B | что изменится от правок или другой версии | что сравниваем (бой или уровень из соседних вкладок), версию и правки варианта B |
| Перебор | при каком значении ячейки бой или уровень становится проходимым | лист, строку, колонку, от, до, шаг и что считать |
| История | что уже считали | последние 30 прогонов: «в форму» и «ссылка» |

Результат появляется под вкладкой и начинается с вывода крупно: процент побед или прохождения и словами — «проходится уверенно» (от 90 %), «проходится, но с риском» (60–90 %), «сложный» (30–60 %), «почти не проходится» (меньше 30 %). Для уровня — ещё «чаще всего умирают на этапе N», для сравнения — разница B − A, для перебора — где проходит порог 50 %. Подробные таблицы свёрнуты ниже и выгружаются в CSV.

| Результат | Что внутри |
| --- | --- |
| Один бой | победа или поражение, ходы, ХП до и после, урон по источникам, бой по ходам |
| Серия | процент побед, типичная длина боя и ХП после победы, разброс (мин, среднее, медиана, p90, макс), доли урона по источникам, проигранные бои по ссылкам |
| Уровень | таблица этапов: дошли, погибли, смертность (этапы, где гибнет каждый пятый, красные), ХП и уровень опыта после этапа; разброс по прогонам; какие перки брал бот |
| Сравнение | A, B и B − A по ключевым числам; для уровня — смертность по этапам |
| Перебор | график и все точки |

Источники урона:
- `attack` — обычная атака;
- `combo1`, `combo2` — комбо;
- `counter` — контратака;
- `skill` — скилл героя;
- `summon` — саммоны;
- `status` — тики статусов;
- `perk` — перки;
- `other` — всё остальное.

## Прогон уровня

Вкладка «Уровень». Каждый прогон — забег с нуля тем же `RunEngine`, что у игроков: раскладка этапов, события, награды, опыт, повышения уровня и выбор перков, ХП между боями, бонусы забега и аккаунта из наград. Из сетапа берутся персонаж, промоут, саммоны, снаряжение и бонусы аккаунта. Перки, бонусы, статусы и ХП забега из сетапа не используются — забег начинается как у игрока.

| Политика | Варианты |
| --- | --- |
| Перки | первый из предложенных; случайный; по списку приоритетов (берётся первый предложенный из списка, остальное добирается первыми предложенными) |
| Развилки | всегда кнопка 1; всегда кнопка 2; случайно |

Что показывает:
- процент прошедших уровень, число боёв и побед;
- распределения: пройдено этапов, уровень опыта в конце, перков за забег;
- таблица по этапам: сколько дошли, прошли и умерли, смертность, среднее ХП и доля ХП после этапа, уровень опыта после этапа, какие id этапов выпадали на этой позиции. Этапы со смертностью от 20 % подсвечены;
- перки: сколько раз предложен, сколько взят, доля взятий;
- сиды проваленных прогонов (до 20).

Награды профиля (ресурсы, предметы, копии) применяются к профилю в памяти и пропадают после прогона; влияют на забег только бонусы аккаунта. Прогон с сидом `N` — это забег с `seed = N` и пустым ключом боя, поэтому прогоны воспроизводимы.

## Черновые правки конфигов

Раздел «Конфиги и правки «что если»» в панели слева — по строке на правку: лист (выбирается из списка), строка, колонка (подсказывается по листу), значение; «+ ещё правка» добавляет строку, «×» очищает. Через API правка — `{ sheet, row, column, value }`; в старых сценариях — текст `лист | строка | колонка | значение`, он читается как раньше. Правки ложатся поверх выбранной версии только для песочницы: ничего не публикуется, у игроков ничего не меняется. Действуют во всех кнопках — характеристики, бой, серия, прогон уровня, сравнение и перебор.

| Часть | Как писать |
| --- | --- |
| лист | имя листа как в снапшоте: `Enemies`, `Constants`, `Exp_levels_patterns`… (регистр не важен) |
| строка | `колонка=значение`, несколько условий через `;` (`id=1;exp_level=3`) — правка ляжет на все подходящие строки; или номер строки листа `#3` (с единицы) |
| колонка | имя колонки как в листе: `health`, `constant_value`, `exp_for_next_lvl`… |
| значение | новое значение ячейки как текст в таблице; для флагов `true` / `false` |

Примеры:

```text
Enemies | id=10101 | health | 900
Constants | constant_name=max_health_base | constant_value | 700
Exp_levels_patterns | id=1;exp_level=3 | exp_for_next_lvl | 30
```

Черновик собирается тем же сборщиком и проходит ту же проверку, что и публикация: опечатка в листе, строке или колонке, нечисловое значение в числовой колонке — ошибка с номером правки, бой не считается. Версия черновика в ответах и истории — `<версия>+draft`. Не больше 200 правок за раз.

## Сравнение A/B

Вкладка «Сравнить A/B»: A — версия и правки из панели слева, B — версия и правки варианта B. Герой, бой или уровень (из вкладок «Бой» и «Уровень»), число боёв или прогонов и сиды одинаковые, поэтому разница — только от конфигов. Сравнивать можно серию боёв (процент побед, ходы, ХП после победы, урон) или прогон уровня (доля прошедших, этапы, уровень опыта, смертность по этапам). Через API можно сравнить и два разных сетапа — у A и B свой `setup`.

## Перебор параметра

Вкладка «Перебор»: лист, строка, колонка, от, до, шаг и что считать — бой или уровень. В каждой точке значение ячейки подставляется поверх версии и правок из панели слева, считается серия (сколько боёв — из вкладки «Бой») или прогон уровня (сколько прогонов — из вкладки «Уровень»). Результат — график процента побед или доли прошедших уровень и таблица по точкам; точка с ошибочным значением показывает ошибку, остальные считаются.

Ограничения: не больше `Balance:MaxSweepPoints` точек, суммарно не больше `Balance:MaxSweepBattles` боёв или `Balance:MaxSweepRuns` прогонов уровня.

## Сценарии и история

- Меню «Сценарии» вверху справа: «Сохранить всю форму как» запоминает всё: версию, сетап, правки, бой, уровень, политики, сравнение и перебор. Сохранение под тем же названием перезаписывает сценарий. Загрузить может любой, удалить — роль `admin`. Хранятся в Mongo, коллекция `balance_scenarios`.
- Каждая серия, прогон уровня, сравнение и перебор пишется в историю: кто, когда, версия, число правок, краткий итог и состояние формы. Вкладка «История» показывает последние 30; «в форму» подставляет сетап того прогона, «ссылка» — то же самое, чтобы переслать. Хранится 90 дней, коллекция `balance_runs` с TTL-индексом.

Админка ходит в API одним ключом, `RateLimit:Admin` по умолчанию — 600 запросов в минуту на каждый логин админки. Справочник версии и список версий страница кэширует; одно нажатие — это обычно 3 запроса к API. Если лимит всё же кончился, админка пишет, через сколько секунд повторить.

## Очередь прогонов

Серия, прогон уровня, сравнение и перебор из админки уходят в очередь (`balance_jobs`) и считаются фоновым воркером внутри API по одному: страница сразу открывает карточку прогона с полосой прогресса и обновляется сама каждые 3 секунды, пока прогон не досчитается. Карточку можно закрыть и вернуться по ссылке позже — результат сохранится. Если API перезапустили посреди прогона, через `Balance:JobStaleSeconds` без новостей прогон помечается ошибкой «worker stopped», его нужно запустить заново. В очереди не больше `Balance:MaxPendingJobs` прогонов; задачи хранятся 7 дней.

Воркер включается `Balance:WorkerEnabled` (по умолчанию да). Он работает в процессе API, но не в потоках запросов игроков; синхронные эндпоинты `/series`, `/level`, `/compare`, `/sweep` остались для скриптов и делят с воркером один слот — одновременно считается один тяжёлый прогон.

## Ссылки и CSV

- У каждого результата из истории есть ссылка `…/Balance?env=dev&run=<id>`: она открывает форму с сетапом того прогона. В таблице «История прогонов» — колонка «ссылка».
- Сиды поражений серии — ссылки `…&run=<id>&battleSeed=<сид>`: открывают именно этот бой пошагово. Ссылку можно переслать.
- `…/Balance?env=dev&Version=<версия>` открывает песочницу на выбранной версии — так работает ссылка из «Проверить баланс».
- Над каждой таблицей результатов — кнопка «CSV»: скачивает таблицу как есть (разделитель `;`, UTF-8 — открывается в Excel и Google Таблицах).

## Типичный игрок на прогрессе

Панель слева → «Взять готовый сетап» → «Типичный игрок, который прошёл уровень»: выбрать уровень и нажать «Подставить». Песочница берёт до 500 последних игроков окружения, которые прошли этот уровень, но не следующий, без тестовых аккаунтов, считает силу героя каждого (МАКС.ХП × ДМГ × АТК_МН с бонусами аккаунта, снаряжением и саммонами) и подставляет в форму сетап игрока с медианной силой. Под кнопкой — сколько таких игроков и медианы промоута, уровней саммонов и снаряжения, числа бонусов аккаунта. Если игроков нет — сообщение, форма не меняется.

## Детерминизм

Одинаковые сетап, версия конфигов и сид дают один и тот же бой. Серия из N боёв идёт по сидам подряд, начиная с указанного. Сид поражения из серии можно вставить в поле «Сид» и посмотреть этот бой пошагово через «Один бой».

Снапшот боя собирается тем же `RunSnapshotBuilder`, что и в забеге. Разница с реальным боем возможна только в том, что песочница не воспроизводит историю забега до этого боя: она использует ХП, перки, бонусы и статусы ровно так, как их указали.

## Admin API

Все запросы — на ops-порту с ключом `X-Admin-Key`.

| Метод | Путь | Что делает |
| --- | --- | --- |
| `GET` | `/admin/balance/versions` | последние 20 снапшотов конфигов и пометка активного |
| `GET` | `/admin/balance/catalog?version=` | справочник для формы: персонажи, саммоны, снаряжение, бонусы, перки, статусы, уровни с этапами и событиями-боями, враги |
| `POST` | `/admin/balance/characteristics` | характеристики по слоям |
| `POST` | `/admin/balance/battle` | один бой |
| `POST` | `/admin/balance/series` | серия боёв |
| `POST` | `/admin/balance/level` | N прогонов уровня |
| `POST` | `/admin/balance/compare` | сравнение A/B: серии или прогоны уровня |
| `POST` | `/admin/balance/sweep` | перебор значения ячейки |
| `GET` | `/admin/balance/scenarios` | список сценариев без содержимого |
| `GET` | `/admin/balance/scenarios/{id}` | сценарий с содержимым |
| `POST` | `/admin/balance/scenarios` | сохранить сценарий `{ name, payload }`, id — название в нижнем регистре |
| `DELETE` | `/admin/balance/scenarios/{id}` | удалить сценарий |
| `GET` | `/admin/balance/history?limit=` | последние прогоны (по умолчанию 50, максимум 200) |
| `GET` | `/admin/balance/history/{id}` | прогон из истории с состоянием формы |
| `POST` | `/admin/balance/jobs` | поставить прогон в очередь: `{ "kind": "series" \| "level" \| "compare" \| "sweep", "request": { …тело соответствующего эндпоинта… } }` → `202 { id }` |
| `GET` | `/admin/balance/jobs/{id}` | статус прогона: `queued` / `running` / `done` / `failed`, `done` и `total`, ошибка, `result` и `runId` по готовности |
| `GET` | `/admin/balance/progress?storyLevelId=&version=` | типичный игрок на прогрессе: число игроков, распределения, `userId` и `setup` медианного |

Тело `POST`:

```json
{
  "version": "",
  "setup": {
    "characterId": 1,
    "promoteLevel": 1,
    "currentHealth": 0,
    "summons": [{ "id": 1, "level": 10, "masteryLevel": 2, "skillLevels": [] }],
    "equipment": [{ "configId": 1, "level": 3 }],
    "accountBonuses": [{ "id": 1, "count": 2 }],
    "runPerks": [2],
    "runBonuses": [{ "id": 3, "count": 1, "remainingBattles": 0 }],
    "runStatuses": []
  },
  "target": { "storyLevelId": 1, "stageId": 3, "eventId": 2, "enemyIds": [] },
  "seed": 1,
  "battles": 200,
  "includeLog": true
}
```

В логах сервера — тег `[Balance]`: каждая серия (кто, версия, персонаж, бой, число боёв, победы, время) каждый прогон уровня (кто, версия, персонаж, уровень, прогонов, прошли, политики, время), сравнение и перебор, а также сохранение и удаление сценариев, постановка прогона в очередь (`[Balance] job queued`), его итог (`job done` / `job rejected`) и сбой воркера (`[Error] balance job failed`). Ошибка записи истории — предупреждение `[Balance] history write failed`, на результат расчёта не влияет, отказы по сетапу и отказ из-за уже идущей серии. Действия в панели дополнительно пишутся в её `audit.log`.

Тело `POST /level`:

```json
{
  "version": "",
  "setup": { "characterId": 1, "promoteLevel": 1, "summons": [], "equipment": [], "accountBonuses": [] },
  "storyLevelId": 1,
  "seed": 1,
  "runs": 100,
  "perkPolicy": "priority",
  "perkPriority": [5, 2],
  "forkPolicy": "random"
}
```

`perkPolicy` — `first`, `random` или `priority`; `forkPolicy` — `firstButton`, `secondButton` или `random`. `runs` ограничено `Balance:MaxLevelRuns`. Серия, прогон уровня, сравнение и перебор делят один слот: пока идёт одно, остальные получают `409`.

Все `POST` для расчётов принимают `edits` — список правок `{ "sheet", "row", "column", "value" }` — и необязательный `scenario` (строка до 64 КБ, её песочница сохраняет в историю как есть). Ошибка в правках — `400` с текстом.

Тело `POST /compare`:

```json
{
  "kind": "series",
  "a": { "version": "", "edits": [], "setup": { "characterId": 1 } },
  "b": { "version": "", "edits": [{ "sheet": "Enemies", "row": "id=10101", "column": "damage", "value": "100" }], "setup": { "characterId": 1 } },
  "target": { "storyLevelId": 1, "stageId": 3, "eventId": 2 },
  "storyLevelId": 1,
  "seed": 1,
  "battles": 200,
  "runs": 100
}
```

`kind` — `series` (используются `target` и `battles`) или `level` (`storyLevelId`, `runs` и политики, как в `/level`).

Тело `POST /sweep` — как у `/compare` с одним вариантом (`version`, `edits`, `setup` на верхнем уровне) плюс `axis`:

```json
{ "axis": { "sheet": "Enemies", "row": "id=10101", "column": "damage", "from": 20, "to": 140, "step": 20 } }
```

Пустой `version` означает мастер. Неизвестная версия — `404`, ошибка в сетапе (нет персонажа, события, врага) — `400` с текстом. `battles` ограничено `Balance:MaxSeriesBattles`. Серии идут по одной на инстанс: пока считается одна, вторая получает `409`.

## Включение

Раздел работает, когда включены `Admin:Enabled`, `Mongo:Enabled` и `Balance:Enabled`. `Balance:Enabled` включён в Local, Development и Staging, в Production валидатор не даёт серверу стартовать с этим флагом. Ключи — [configuration.md](../runbooks/configuration.md#balance).
