# Снаряжение

Источник: GDD «Снаряжение» (версия 2026-10-02). Настройка — листы `Equipments` и `Equipment_promotes`.

## Конфиг `Equipments`

| Колонка | Что внутри |
| --- | --- |
| `id` | id предмета |
| `type` | вид: `body`, `pants`, `boots`, `necklace`; определяет слот |
| `rarity` | техническое название редкости |
| `promote_id` | ссылка на ветку уровней в `Equipment_promotes` |
| `bonus_ids` | id бонусов из `Bonuses` через `;` |
| `skill_ids` | id скиллов из `Skills` через `;` |
| `merge_group`, `merge_number` | ветка трансформации и позиция в ней |
| `merge_requirements` | плата за трансформацию |
| `art_name` | имя ассета арта |

У одного игрока может быть несколько копий одного предмета, каждая качается отдельно.

## Редкости

Основные редкости повышают статы, задают цвет фона и меняют числа или механики скиллов; побочные стоят между основными и нужны только для трансформации. По возрастанию: `common`, `uncommon`, `rare`, `epic`, `epic_1`, `epic_2`, `legendary`, `legendary_1`, `legendary_2`, `legendary_3`, `mythic`, `mythic_1`, `mythic_2`, `mythic_3`, `mythic_4`.

В `RarityType` значения добавлены в конец перечисления, поэтому числовой порядок enum не совпадает с порядком редкостей — сравнивать редкости числом нельзя, только на равенство.

## Бонусы

Предмет несёт сколько угодно бонусов, они перечислены в `bonus_ids`. Значение берётся из самого бонуса по текущему уровню предмета: `bonus_value` это список значений через `;`, уровень 1 берёт первое значение. Если значений меньше, чем уровень, сервер берёт последнее и пишет предупреждение. Привязка бонуса к предмету — через `work_modes` вида `if_equipped:equipments:<id>`; сервер принимает и единственное число (`if_equipped:equipment:<id>`), потому что в листах встречается оба написания.

## Прокачка по уровню

Стоимости лежат в `Equipment_promotes`:

| Колонка | Что внутри |
| --- | --- |
| `id` | ветка уровней, на неё ссылается `promote_id` предмета |
| `level` | уровень, **на который** предмет перейдёт (первого уровня в таблице нет) |
| `resource_types`, `resource_ids`, `resource_values` | произвольное число наград, нужных для перехода |

Поддерживается только тип `resource`; ресурсы прокачки — `equip_lvl` и `equip_break`. Максимальный уровень предмета определяется последней строкой его ветки.

## Сброс уровня

Уровень падает до первого, на аккаунт возвращается округлённое `сумма потраченного до текущего уровня * equipment_lvl_drop_proportion`. Сумма считается по `Equipment_promotes` за все уровни от второго до текущего. В тексте ГДД константа названа `equipment_lvl_drop_coeff`, в листе `Constants` она лежит как `equipment_lvl_drop_proportion` — сервер читает имя из листа. Стоимость самого сброса задаётся константой `equipment_lvl_drop_resource`; её в листе нет, поэтому сброс бесплатный.

## Трансформация

Требования перечислены в `merge_requirements`, разделитель компонентов `;`, внутри требования `:`:

- `equipment_id:<id>:<кол-во>` — столько-то копий конкретного предмета;
- `equipment_rarity:<редкость>:<кол-во>` — столько-то предметов того же вида, что трансформируемый, указанной редкости.

Количество можно не указывать, тогда оно равно 1. Пустой `merge_requirements` означает, что предмет не трансформируется. Платой может быть любое снаряжение в инвентаре, кроме трансформируемого.

При успешной трансформации: трансформируемый предмет и плата удаляются, выдаётся предмет той же `merge_group` с `merge_number` на 1 больше, его уровень равен уровню исходного, и если исходный был экипирован, новый автоматически встаёт в освободившийся слот.

## Скиллы

Скиллы предмета берутся из `skill_ids` и работают по общей механике скиллов ([`12-skills.md`](12-skills.md)). Скилл оружия активируется по ЭНЕРГИИ.
