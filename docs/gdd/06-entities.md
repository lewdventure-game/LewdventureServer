# Сущности: персонажи, мобы, саммоны

Источник: GDD «Персонажи», «Мобы», «Саммоны».  
Бой — [`01-battle-loop.md`](01-battle-loop.md). Визуал — [`02-presentation-contract.md`](02-presentation-contract.md).

## Общее правило

Сервер знает id, уровни, пресеты, скиллы и считает их влияние на бой.  
Клиент подставляет art/анимации/звуки по id.

Прокачка/коллекция на аккаунте — future meta; в battle-скоупе сервер получает **уже собранный snapshot** стороны (или собирает его из конфигов + переданных уровней).

## Персонажи

Основной юнит игрока.

### Бой

- Использует **итоговые характеристики аккаунта** на момент действия (см. [`04-characteristics-bonuses.md`](04-characteristics-bonuses.md)).
- `is_melee` в Characters: ближник подходит и возвращается; иначе ranged без возврата.
- Есть пассивные скиллы персонажа (не energy); логика уникальна per-skill.
- Energy-скилл оружия — отдельный этап хода (см. battle loop).

### Визуал (клиент)

Battle sprite, idle/attack/hit/death, 3 типа атаки от оружия, cast energy, meta sprite, reward icon.  
Bundle id: `art_name`.

### Получение и прокачка

- Reward type `character`.
- Первый дроп: персонаж открывается сразу на **1 уровне прокачки** (ГДД 2026-10-04): строка `promote_level = 1` в `Character_promotes` стоит 0 копий и применяется автоматически вместе с её наградами.
- Повторки → промоуты по листу `Character_promotes`; overflow сверх последнего уровня → `character_overflow_resource` (meta).

**Промоуты (лист `Character_promotes`, подключён 2026-09-30):**

- Персонаж ссылается на набор промоутов через `promote_id`; строки набора нумерованы `promote_level` (1, 2, 3 …).
- `copies_to_upgrade` — цена уровня в повторках, у первого уровня 0. Копии тратятся автоматически, пока хватает на следующий уровень; отрицательная цена останавливает прокачку с предупреждением.
- `frame_id` — рамка/ранг для визуала, сервер только отдаёт значение.
- `reward_types` / `reward_ids` / `reward_values` — награды за уровень тремя параллельными колонками через `;`. Внутри встречаются `resource`, `bonus` (постоянный бонус на аккаунт) и `story` (сцена персонажа: id складывается в `characters[].unlockedScenes` того персонажа, чей промоут выдал награду).
- Бонусы за прокачку теперь приходят наградой на аккаунт и попадают в бой через `activeBonuses`, а не считаются в билде из Characters.
- `promote_to_skill_levels` в Characters — уровни промоута (с 1), на которых скилл переходит на следующий набор значений: при `1;2;4;6` уровень 1 берёт первые значения, 2 и 3 — вторые, 4 и 5 — третьи. Подробно — [12-skills.md](12-skills.md).

В профиле уровень хранится как `characters[].promoteLevel`; в snapshot боя `level` = этот уровень (1 и выше).

## Мобы

Вражеские юниты. Конфиг Enemies (+ пресеты характеристик).

### Пресеты и характеристики

Характеристики моба задаются итоговыми значениями в конфиге/пресете (могут модифицироваться эффектами игрока в бою).
`is_melee` в Enemies: ближник подходит и возвращается; иначе ranged без возврата.

### Скиллы мобов

Уникальная логика; сервер исполняет в фазах unit skill / energy (если есть).

### Визуал (клиент)

Отдельный раздел GDD «Визуальные ассеты мобов» — art, анимации; сервер шлёт id и события.

### Мульти-моб

Расстановка 1–2 мобов — презентация; логика выбора цели атак — уточнить в детальном плане (сейчас GDD в атаках говорит «юнит защищающейся стороны» — нужна каноническая цель при 2 мобах).

## Саммоны

Второстепенные юниты игрока в бою. Конфиги (ГДД 2026-10-04): `Summons`, `Summon_levels`, `Summon_masteries`, `Skill_promotes`.

### Лист Summons

`id`, `art_name`, `is_melee`, `rarity`, `dmg_on_lvls`, `attack_cooldown`, `mastery_id` (набор в `Summon_masteries`), `level_pattern_id` (набор в `Summon_levels`), `skill_ids`, `mastery_for_skills`, `skill_upgrade_ids` (наборы в `Skill_promotes`). Три последних — параллельные списки через `;`: i-е значение относится к i-му скиллу.

### Бой

Порядок действий — слоты 1→2→3 в фазе саммонов.

**ДМГ саммона (личный):** `dmg_on_lvls[level - 1] * Summon_masteries(mastery_id, masteryLevel).dmg_multiplier`; уровень выше длины списка берёт последнее значение.

- Не равен ДМГ аккаунта.
- Крит обычной атаки саммона использует КРИТ_МН **атакующего юнита** стороны.
- `is_melee` в Summons: ближник подходит и возвращается; иначе ranged без возврата.
- `attack_cooldown`: после фактической атаки (включая промах) N полных ходов до следующей; 0 = каждый ход; не ударил на готовом ходе — кулдаун не стартует. Атака доступна с первого хода.
- Скиллы: из `skill_ids` в бой попадают только открытые по мастерству (`masteryLevel >= mastery_for_skills[i]`). У каждого скилла свой уровень: snapshot несёт `skillLevels` (по порядку `skill_ids`, нет значения — 1), скилл берёт значения с номером, равным уровню.
- Бонусы мастерства в бою больше не считаются: награды мастерства (в том числе `bonus`) выдаются разово на аккаунт и приходят в бой через `activeBonuses`.

### Редкость

Rarity: rare / epic / legendary (фон карточки — клиент). Не прокачивается.

### Получение и прокачка

- Reward `summon`. Первая копия открывает саммона с уровнем 1 и мастерством 1 и сразу выдаёт награды строки `mastery_level = 1` из `Summon_masteries`; дальнейшие — копии (`copies`).
- **Уровень** (`POST /api/player/summon/level`): строка `Summon_levels` с `pattern_id = level_pattern_id` и `level` = уровень, **на который** переходит саммон (первой строки нет). Ресурсы — `resource_types/ids/values` (сейчас `summon_lvl`, на рубежах ещё `summon_break`). Мастерство уровень не ограничивает; потолок — последняя строка набора.
- **Сброс уровня** (`POST /api/player/summon/level/reset`): уровень → 1, каждый потраченный ресурс возвращается по `summon_level_reset_coeff`, сброс стоит `summon_level_reset_resource`. Мастерство и уровни скиллов не трогаются.
- **Мастерство** (`POST /api/player/summon/mastery`, кнопка): списывает `copies_to_upgrade` следующего уровня и выдаёт награды этого уровня (`reward_types/ids/values`; `story` открывает сцену саммона в `summons[].unlockedScenes`). Копии сверх максимального мастерства конвертируются по константе редкости.
- **Скилл** (`POST /api/player/summon/skill/level`): строка `Skill_promotes` с `pattern_id = skill_upgrade_ids[i]` и `level` = уровень, на который переходит скилл; нужен уровень саммона не ниже `level_to_unlock` и открытый по мастерству скилл. Уровни хранятся в `summons[].skillLevels`.
