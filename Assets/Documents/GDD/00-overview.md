# Overview: сервер и клиент Lewdventure

## Роли


| Сторона                               | Роль                                                                                                         |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| **Сервер (этот проект)**              | Источник истины. Знает конфиги, считает бой и связанные системы, отдаёт клиенту данные и script презентации. |
| **Клиент (Unity,** `Lewdventure`**)** | Презентер. Слушает сервер, воспроизводит команды, не принимает самостоятельных gameplay-решений.             |


Клиент **не** пересчитывает урон, крит, уклон, стаки статусов, исход боя.  
Если клиенту нужно что-то показать — сервер уже положил это в ответ (шаг, команда, параметр).

## Scope

### Сейчас (battle)

Реализуем на сервере всё, что нужно для боя:

- цикл хода и фазы (статусы → перки → саммоны → юнит → энергия);
- характеристики и бонусы в бою;
- статусы, перки, скиллы, саммоны, снаряжение как влияние на бой;
- детерминированный RNG (seed);
- battle script для клиента;
- конфиги (Google Sheets → mapper managers).



### Потом (meta)

Не в текущем scope реализации, но учитывать в модели мира:

- профили пользователей;
- валюты и ресурсы аккаунта;
- сохранения / прогресс забега вне боя;
- постоянные награды вне battle response.

В документах meta упоминается только там, где GDD связывает награду/прокачку с будущим аккаунтом.

## Конфиги

Сервер владеет игровыми конфигами и индексами (`IConfigDistributor`, `*MapperManager`).  
Клиент может получать нужные ему для UI/визуала срезы **от сервера**, а не считать себя владельцем баланса.

## Логирование

Цель: verbose diagnostics при разработке.

Уже встречающиеся префиксы в коде:

- `[Error]`
- `[Error][Story][Battle]`
- `[Story][Battle] (всегда идут в паре)`

**Правило:** перед введением нового лог-тега — согласовать с владельцем проекта.  
Не придумывать `[Battle]`, `[Config]` и т.п. без явного ОК.

## Код: запрет static

В новой/дорабатываемой серверной логике **не использовать static** для gameplay-состояния, синглтонов симуляции, кэшей без DI.  
Зависимости — через конструктор / DI.
