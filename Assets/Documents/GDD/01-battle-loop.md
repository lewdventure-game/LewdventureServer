# Битва: цикл и логика (сервер)

Источник: GDD «Битва».  
Презентация (позиции, анимации, flytext) — [`02-presentation-contract.md`](02-presentation-contract.md).

## Термины

- **Юнит** — главная боевая сущность стороны (персонаж игрока или моб).
- **Сторона** — атакующая или защищающаяся.
- В начале битвы игрок **всегда** на атакующей стороне.
- Когда атакующая сторона завершила все действия, стороны меняются местами.

## Ходы

- После того как обе стороны побывали атакующими в одном ходе, счётчик хода +1.
- `maxTurns` задаётся параметрами режима / story level.
- Если враги не убиты к концу последнего хода — поражение (timeout).

## Порядок действий атакующей стороны

Триггерится, когда сторона становится атакующей.

### 1. Очередь статусов

- Статусы **на юните атакующей стороны**, которые срабатывают по ходам и могут сработать сейчас.
- Порядок: возрастание `proc_order` из конфига Statuses.
- Пауза между срабатываниями: `statuses_cooldown` (Constants), в секундах для презентации; сервер эмитит Wait/cooldown в script.
- После последнего статуса — ещё одна пауза `statuses_cooldown`, затем следующая фаза (сервер: trailing Wait даже при пустой очереди).
- Death-time resurrection во время фазы → abort оставшегося side-turn.

### 2. Очередь перков

- Перки **атакующей стороны**, срабатывающие по ходам и доступные на текущем ходе.
- Порядок: возрастание `proc_order` из конфига Perks.
- Пауза: `perks_cooldown` (Constants).

### 3. Действия саммонов

По слотам 1 → 2 → 3 (если слот занят):

1. Саммон использует все доступные на этом ходе скиллы (логика per-summon).
2. Затем обычная атака по **юниту** защищающейся стороны.
3. Обычная атака саммона может критовать (крит-шанс **атакующего юнита** стороны).
4. Защитник может уклониться (итоговый УКЛОНЕНИЕ защитной стороны).
5. Если саммон был в ближнем положении — возврат на место.
6. Пауза `summons_cooldown` перед следующим саммоном / следующей фазой.

**Урон саммона**

- Обычный: `итоговый ДМГ саммона * (1 - итоговая ЗАЩИТА защитника)`
- Крит: `(итоговый ДМГ саммона * итоговый КРИТ_МН атакующего юнита) * (1 - ЗАЩИТА защитника)`

### 4. Действия атакующего юнита

1. Скиллы персонажа (не energy-скилл оружия), доступные на ходе.
2. Пауза `units_cooldown`.
3. Обычная атака по юниту защитника:
   - может критовать (КРИТ_ШАНС атакующего);
   - можно уклониться (УКЛОНЕНИЕ защитника).
4. Контратака защитника с шансом КОНТР_ШАНС (после паузы `counterattack_cooldown`):
   - может критовать / можно уклониться;
   - **контратака не триггерит контратаку**.
5. Комбо 1 с шансом КОМБО_1_ШАНС (`comboattack_cooldown`), затем снова возможна контратака.
6. Комбо 2 с шансом КОМБО_2_ШАНС, затем снова возможна контратака.
7. Возврат на дальнее положение.
8. Скилл энергии, если `энергия >= ЭНЕРГИЯ_МАКС`:
   - пауза `units_cooldown`;
   - урон скилла **не критует**;
   - можно уклониться;
   - **не триггерит контратаку**.

**Урон обычной атаки юнита**

- Обычный: `(ДМГ * АТК_МН) * (1 - ЗАЩИТА)`
- Крит: `(ДМГ * АТК_МН * КРИТ_МН) * (1 - ЗАЩИТА)`

**Урон контратаки**

- Обычный: `(ДМГ защитника * КОНТР_МН) * (1 - ЗАЩИТА атакующего)`
- Крит: `(ДМГ * КОНТР_МН * КРИТ_МН) * (1 - ЗАЩИТА атакующего)`

**Урон комбо**

- Комбо 1: `(ДМГ * КОМБО_1_МН) * (1 - ЗАЩИТА)` (+ крит с КРИТ_МН)
- Комбо 2: `(ДМГ * КОМБО_2_МН) * (1 - ЗАЩИТА)` (+ крит с КРИТ_МН)

> В таблице характеристик GDD также есть `КОМБО_МН`; при детальном плане сверить, какой множитель каноничен для комбо 1/2.

## RNG и детерминизм

- Все шансы (крит, уклон, контр, комбо, перки) — через seeded RNG на сервере.
- Seed уходит клиенту в ответе для replay/отладки, не для пересчёта логики клиентом.

## Исход боя

Сервер определяет outcome (победа стороны / timeout / …) и кладёт в response.  
Клиент только показывает результат по команде сервера.
