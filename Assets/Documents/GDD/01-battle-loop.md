# Битва: цикл и логика (сервер)

Источник: живая вкладка GDD «Битва» (`t.8eajrxiobtkp`) + канон владельца 2026-09-10.  
Паста правок текста вкладки: клиент `.ai-factory/specs/gdd-battle-paste.md`.  
Презентация (позиции, анимации, flytext) — [`02-presentation-contract.md`](02-presentation-contract.md).  
Множитель комбо — [`04-characteristics-bonuses.md`](04-characteristics-bonuses.md): один `combo_multiplier_*` на оба удара.

Нет fallback: дырка константы / маппера / `proc_order` — ERROR, симуляция не продолжает с нулём.

## Термины

- **Юнит** — главная боевая сущность стороны (персонаж игрока или моб).
- **Сторона** — атакующая или защищающаяся.
- В начале битвы игрок **всегда** на атакующей стороне.
- Когда атакующая сторона завершила все действия, стороны меняются местами.

## Ходы

- Полный ход: сторона A (игрок, всегда первая) → сторона B → счётчик хода +1.
- `maxTurns` задаётся параметрами режима / story level.
- Если враги не убиты к концу последнего хода — поражение (timeout).

Воскрешение-abort полного хода **не описано** во вкладке «Битва». Правило в коде перка — вне скоупа сверки этой вкладки; из канона этой вкладки его не выводить и не выкидывать в рамках плана вкладки.

## Порядок действий атакующей стороны

Триггерится, когда сторона становится атакующей.

Wait фазы: `*_cooldown` после **каждого** элемента очереди и после последнего. Очередь: элемент wait элемент wait. Пустая очередь — 0 wait, сразу следующая фаза. Отдельного второго wait поверх последнего нет.

### 1. Очередь статусов

- Статусы **на юните (main) атакующей стороны**, которые срабатывают по ходам и могут сработать сейчас. Саммоны в очередь тиков **не** входят.
- Несколько main (два моба): сначала весь `proc_order` слота с меньшим индексом, затем следующего живого main.
- Порядок внутри юнита: возрастание `proc_order` из конфига Statuses.
- Пауза между срабатываниями и после последнего **сработавшего**: `statuses_cooldown` (Constants). Очередь: статус wait статус wait. Пустая очередь — без wait.
- Элемент очереди = срабатывание даже при нулевом уроне; Wait не пропускать из‑за `damage <= 0`. `SetHp` — если этот статус изменил HP (как после любого другого изменения HP). Статус без изменения HP `SetHp` не шлёт. Это не «SetHp после каждого статуса» и не «статусы SetHp не используют».
- Если тик убивает юнита: остальные статусы этого юнита **не** тикают и wait по ним нет. Следующий живой main продолжает свою очередь. Живых main не осталось — остаток хода этой стороны (перки, саммоны, атаки) не выполняется, ход переходит к другой стороне.
- `damage_length` тратится только у статусов, которые реально тикнули.

### 2. Очередь перков

- Перки **атакующей стороны**, срабатывающие по ходам и доступные на текущем ходе.
- Порядок: возрастание `proc_order` из конфига Perks. Нет `proc_order` — ERROR.
- Пауза: `perks_cooldown` между срабатываниями и после последнего (перк wait перк wait). Пустая очередь — без wait.

### 3. Действия саммонов

Саммоны **стоят в слотах до конца боя**. Сервер в старте script шлёт `SpawnUnit` (поставить в слот). Живых саммонов в конце **не** снимает `DespawnUnit`. Смерть саммона в ходе — `KillUnit`, если логика так сказала.

По слотам 1 → 2 → 3 (если слот занят):

1. Скиллы, доступные на этом ходе (логика per-summon). `summons_cooldown` после каждого скилла, включая последний.
2. Обычная атака по **юниту** защищающейся стороны — только если саммон **может атаковать на этом ходу**.
   - Атака доступна с первого хода.
   - После фактической атаки (включая промах) кулдаун `attack_cooldown` полных ходов из Summons: 0 — можно на следующем ходу; 2 — удар на 1-м, следующий на 4-м.
   - Не ударил на готовом ходе (стан и т.п.) — кулдаун не стартует.
3. Обычная атака саммона может критовать (крит-шанс **атакующего юнита** стороны).
4. Защитник может уклониться (итоговый УКЛОНЕНИЕ защитной стороны).
5. Тег `is_melee` из Summons: ближник подходит, бьёт, возвращается на слот; иначе дальняя атака без возврата.
6. После атаки (melee — после возврата) — `summons_cooldown`, затем следующий слот. Пропуск атаки wait за неё не даёт.
7. Нет слотов, которые могут скиллить или атаковать на ходе — фаза без wait. Текст «после всех саммонов ещё wait» — это wait после последнего действия, не второй wait сверху.

**Урон саммона**

- Обычный: `итоговый ДМГ саммона * (1 - итоговая ЗАЩИТА защитника)`
- Крит: `(итоговый ДМГ саммона * итоговый КРИТ_МН атакующего юнита) * (1 - ЗАЩИТА защитника)`

### 4. Действия атакующего юнита

Если на стороне несколько живых main (два моба) — во вкладке «Битва» не описано, кто ходит и в кого бьют. Текущий код (все живые main, цель min `slotIndex`) вне скоупа сверки этой вкладки.

1. Скиллы персонажа (не energy-скилл оружия), доступные на ходе.
2. Пауза `units_cooldown`.
3. Обычная атака по юниту защитника:
   - может критовать (КРИТ_ШАНС атакующего);
   - можно уклониться (УКЛОНЕНИЕ защитника).
4. Контр и комбо **только если обычная атака попала**. Промах → возврат на дальнее положение и energy skill (если бар полный), без цепочки.
5. Контратака защитника с шансом КОНТР_ШАНС (после паузы `counterattack_cooldown`):
   - может критовать (КРИТ_ШАНС защищающегося) / можно уклониться (УКЛОНЕНИЕ атакующей стороны);
   - **контратака не триггерит контратаку**.
6. Комбо 1 с шансом КОМБО_1_ШАНС (`comboattack_cooldown`). Контратака на комбо-1 и комбо-2 — **только если комбо-1 попало**. Промах комбо-1 → нет контра на неё, нет комбо-2.
7. Комбо 2 с шансом КОМБО_2_ШАНС, затем снова возможна контратака (если комбо-2 попало).
8. Возврат на дальнее положение.
9. Скилл энергии, если `энергия >= ЭНЕРГИЯ_МАКС`:
   - пауза `units_cooldown`;
   - урон скилла **не критует**;
   - можно уклониться;
   - **не триггерит контратаку**.

**Урон обычной атаки юнита**

- Обычный: `(ДМГ * АТК_МН) * (1 - ЗАЩИТА)`
- Крит: `(ДМГ * АТК_МН * КРИТ_МН) * (1 - ЗАЩИТА)`

**Урон контратаки**

- Обычный: `(ДМГ защитника * КОНТР_МН) * (1 - ЗАЩИТА атакующего)`
- Крит: `(ДМГ защитника * КОНТР_МН * КРИТ_МН) * (1 - ЗАЩИТА атакующего)`

**Урон комбо**

Один итоговый КОМБО_МН на оба удара. Шансы раздельные.

- Обычный: `(ДМГ * КОМБО_МН) * (1 - ЗАЩИТА)`
- Крит: `(ДМГ * КОМБО_МН * КРИТ_МН) * (1 - ЗАЩИТА)`

Раздельные `combo_1_multiplier_*` / `combo_2_multiplier_*` — ERROR (obsolete). Legacy fallback в оба множителя не используется.

## RNG и детерминизм

- Все шансы (крит, уклон, контр, комбо, перки) — через seeded RNG на сервере.
- Seed уходит клиенту в ответе для replay/отладки, не для пересчёта логики клиентом.

## Исход боя

Сервер определяет outcome (победа стороны / timeout / …) и кладёт в response.  
Клиент только показывает результат по команде сервера.
