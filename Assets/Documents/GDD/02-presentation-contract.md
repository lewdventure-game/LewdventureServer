# Контракт презентации (клиент)

Сервер считает истину. Клиент **только** воспроизводит команды из battle script.

Цель файла: сохранить из GDD обязанности клиента (позиции, анимации, flytext, VFX), чтобы при детальных планах не терять UX-ожидания.

## Общий принцип

1. Сервер эмитит упорядоченный список `BattleStep` с `BattleCommand`.
2. Клиент играет команды по порядку; тайминги Wait/cooldown приходят из сервера (на базе Constants).
3. Клиент **не** решает: был ли крит, уклон, какой урон, умер ли юнит, какой статус наложился.
4. Число отыгранных ходов клиент берёт из `steps[].turn` (отдельного `turnsPlayed` нет).
5. `targetId` в step/params: config id цели; **`-1`** если цели нет.
6. Seed RNG приходит только в response (сервер генерирует); клиент не шлёт seed и не пересчитывает бой.

Актуальный protocol (request/response, snapshot, полная таблица `operation → params`): [`.ai-factory/specs/battle-simulation.md`](../../../.ai-factory/specs/battle-simulation.md).  
Handoff для ИИ по клиентской реализации: [`10-client-battle-ai.md`](10-client-battle-ai.md).

## Mapping: логика → команды (ориентир)

| Событие логики | Типичные команды (enum) |
| --- | --- |
| Пауза между фазами | `Wait` |
| Подход melee к цели | `Approach` |
| Возврат на позицию | `ReturnToPosition` |
| Анимация атаки / каста | `PlayAnimation` |
| Урон попал | `ShowDamage`, `SetHp` |
| Уклон | `ShowMiss` (+ движение уклона на клиенте) |
| Лечение | `ShowHeal`, `SetHp` |
| Статус наложен / снят / тик | `ApplyStatus` / `RemoveStatus` / `TickStatus` (+ `ShowDamage` если урон, `SetHp` если HP изменился) |
| Перк | `TriggerPerk` |
| Скилл | `CastSkill` |
| Энергия | `SetEnergy` |
| Смерть / spawn саммона | `KillUnit` / `SpawnUnit` / `DespawnUnit` |
| Конец боя | `SetBattleResult` |

Схема ключей `params` для каждой операции — в таблице `BattleCommandOperation → params` в [battle-simulation.md](../../../.ai-factory/specs/battle-simulation.md).

## Расстановка на локации (клиент)

Настраивается в Unity (расстояния N/M/O/X). Сервер не двигает пиксели — он говорит *когда* approach/return.

Сценарии из GDD:

- персонаж vs персонаж (дальнее положение);
- персонаж vs 1 моб;
- персонаж vs 2 моба;
- ближнее положение юнита / юнита vs второй юнит / саммона.

Слоты саммонов симметричны; позиции согласуются с геймдизайном.

## Уклонение (клиент)

При команде miss/evasion:

- юнит за 0.2 с скользит назад;
- flytext `ui.battle.flytext.miss` (ключ `ui.battle.evasion` не используется), время жизни — `battle_flytext_timer`;
- возврат на исходную точку. Busy playback держится, пока оба слайда не закончатся.

## Обычная атака / контратака / комбо / атака саммона (клиент)

Общий паттерн:

1. Если `is_melee` и юнит в дальнем положении → approach (~0.2 с) по команде сервера.
2. Анимация атаки:
   - ranged: projectile из оружия; момент hit — когда projectile долетел (скорость projectile — Unity); сервер уже зафиксировал hit/miss/crit/damage в script **до** или согласованно с таймингом презентации (детали синхронизации — в будущем detailed plan);
   - melee: hit в тайминг анимации Unity.
3. При получении урона: flash белым ~0.15 с + короткий knockback.
4. Flytext:
   - обычный урон — белый, меньший размер;
   - крит — оранжевый с красной обводкой, больший размер.

## Статусы (клиент)

- Иконка висящего статуса у HP-бара по `icon_art_name` из Statuses (не по `statusId`). Неизвестный art → ERROR, без fallback на соседний id.
- При >1 стака одного `statusId` — цифра стаков.
- `TickStatus` — one-shot VFX **в центре модели** (`Renderer.bounds.center`) по `status_type`: burning / burning_strong → огонь, poison / poison_strong → яд. Сервер шлёт `TickStatus` только для DoT.
- Если статус изменил HP — в script будет `SetHp`. Если нет — не будет. `SetHp` не накладывает статус.
- `bonus_change` не висит: нет `ApplyStatus` / `TickStatus` / иконки; клиент видит только выдачу бонуса (`SetBonus`), если сервер её эмитит.

## Перки (клиент)

- Маленькая иконка / большие плашки выбора.
- Задник и рамка от rarity.
- UI ручного выбора перков (blur, checkbox, confirm) — клиентский UX; **какие** перки показать и что применилось — решает сервер (когда meta/run flow будет на сервере).

## Персонажи / мобы / саммоны / снаряжение (клиент)

Визуал, анимации idle/attack/hit/death/cast, art bundles (`art_name`, skins) — клиент.  
Сервер передаёт id сущностей и события; клиент подставляет ассеты.

## Что клиенту запрещено

- Пересчитывать формулы урона и характеристик.
- Самостоятельно накладывать/снимать статусы «для красоты».
- Менять HP/energy локально без команды сервера.
- Определять исход боя раньше `SetBattleResult`.
