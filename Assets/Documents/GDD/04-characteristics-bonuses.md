# Боевые характеристики и бонусы

Канон: живой GDD, вкладка [«Боевые характеристики и Бонусы»](https://docs.google.com/document/d/1yPcdBVD3Uxbi0aIcv-6wr7ZTSEWUO4e7PV1JhEPoRxw/edit?tab=t.t8eului4weh) (`t.t8eului4weh`), dump 2026-09-10.

Использование в бою — [`01-battle-loop.md`](01-battle-loop.md).

Сервер в каждый момент действия использует **актуальные итоговые** характеристики. Клиент в бою показывает HP/energy/flytext по командам сервера. Попап/HUD вне боя показывает те же итоговые значения, не сырые константы.

Нет fallback: дырка ключа/конфига/`work_mode` — ERROR, симуляция не продолжает с нулём.

## Решения владельца (2026-09-10)

- Формула 3 и слой `*_global` — как в живом GDD. Не переименовывать формулу 3 в «healing from max» и не объявлять её ошибкой документа.
- **СНАР_СПЕЛЛ_МН** (`equip_spell_*`) — устарело. Не реализовывать, не заводить ключи, не показывать в попапе.
- **`health_perk` в примерах GDD = `max_health_perk`.** Алиас `health_perk` в код не заводить.
- При любом изменении МАКС.ХП текущее ХП: `старое_текущее / старое_макс = новое_текущее / новое_макс`.
- **КОМБО_МН** — одна характеристика `combo_multiplier_*`. Один итог множителя на удар комбо-1 и удар комбо-2. `combo_1_chance` / `combo_2_chance` — два отдельных шанса.
- Артефакты, аспекты, ЩИТ — не в демо, не пилить.

## Источники бонусов аккаунта игрока (пополняемо)

- стартовое значение в константах (`названиехарактеристики_base`);
- тренировки;
- снаряжение;
- персонажи;
- саммоны;
- артефакты (не в демо);
- аспекты (не в демо);
- перки.

Характеристики врагов — итоговые значения из конфигов сущностей (могут модифицироваться эффектами игрока).

## Формулы

Бонусы внутри суммы могут быть отрицательными.

1. Итоговая характеристика = математически округлить `((стартовая из константы + сумма базовых) * (1 + сумма минорных) * (1 + сумма мажорных) * (1 + сумма перковых) * (1 + сумма глобальных))`. Итог не меньше 1 (кроме текущего ХП).

2. Итоговая характеристика = `(стартовая из константы + сумма базовых) * (1 + сумма перковых) * (1 + сумма глобальных)`.

3. Итоговая характеристика = `(1 + стартовая из константы + сумма базовых) * (1 + сумма перковых) * (1 + сумма глобальных)`. Итог не меньше 0.

4. Итоговая характеристика = прошлое значение − полученный урон.

5. Итоговая ЗАЩИТА = `defence_coeff * итоговая БРОНЯ / (1 + defence_coeff * модуль итоговой БРОНИ)`.

6. Вампиризм-хил = округлить вверх `(нанесённый урон * (vampyrism_base + сумма базовых) * (1 + сумма перковых) * (1 + сумма глобальных) * итоговая УВЕЛИЧЕНИЕ_ЛЕЧЕНИЯ)`. Не меньше 0. Ставка вампиризма для попапа — множитель без урона (диапазон 0–999, где 1 = 100%).

7. Итоговая УВЕЛИЧЕНИЕ_ЛЕЧЕНИЯ = математически округлить `((1 + healing_boost_base + сумма базовых) * (1 + сумма перковых) * (1 + сумма глобальных))`. Не меньше 0.

«Математически округлить» — к ближайшему, midpoint away from zero, не bankers ToEven.

Энергия за удар не начисляется, если атака промахнулась.

## Бонусы-эффекты

Не складываются в итоговую шкалу, срабатывают эффектом.

| bonus | Формула | bonus_value | work_mode | operator |
| --- | --- | --- | --- | --- |
| `healing_from_max` | `новое текущее = старое текущее + итоговое МАКС.ХП * bonus_value * итоговое УВЕЛИЧЕНИЕ_ЛЕЧЕНИЯ` | дробь от макс.ХП, может быть < 0 | `permanent` — разово при получении | всегда `add` |
| `healing` | `новое текущее = старое текущее + старое текущее * bonus_value * итоговое УВЕЛИЧЕНИЕ_ЛЕЧЕНИЯ` | дробь от текущего ХП, может быть < 0 | `permanent` — разово при получении | всегда `add` |

Ceil в эти формулы не добавлять, в GDD его нет.

## Выдача бонусов

Любой наградной плейсмент: `reward_type = bonus`, `reward_id` = id из конфига Bonuses, `reward_value` = сколько раз выдать.

### operator

| Значение | Поведение |
| --- | --- |
| `add` | `bonus_type` + `bonus_value` добавляется в сумму таких же бонусов |
| `replace` | подменяет итог характеристики, пока бонус действует; после окончания — обратно к формуле с остальными бонусами |

### work_mode

| Значение | Поведение |
| --- | --- |
| `permanent` | навсегда влияет на сумму. Для `healing` / `healing_from_max` — разово при получении |
| `if_equipped:название_сущности:ID` | только пока экипированы `equipments` / `characters` / `summons` |
| `end_of_game` | до конца текущего забега (победа или поражение) |
| `end_of_battle` | до конца текущего боя |
| `next_battles:N` | следующие N битв забега; воскрешение перком не считает бой заново |
| `first_turns:N` | первые N ходов каждого боя забега |
| `every_turn` | каждый ход прибавляет исходное значение к себе (`1.1` → `2.2` → `3.3`); после боя сброс, в следующем бою забега снова с исходного |

Пустой / unknown `work_mode`, `N <= 0` — ERROR, бонус не применяется.
